# Profiling Report — v1.11.46 (2026-11-09)

**Benchmark:** `arith.pas` (1M iterations, for loop)
**Command:** `pascak_noASTnet --profile benchmarks/cross_lang/arith.pas`

## Total Opcode Count

**8,000,024 opcodes** for 1M iterations = **8 opcodes/iteration** (arith loop)

## Key Findings

### 1. `opcGetLocal` is the hotspot (25%)
Register VM Phase 1 would eliminate these 2M opcodes by fusing into register operands.

### 2. For-loop redundancy (compiler bug suspected)
`opcForLoopCond` (fused opcode) coexists with `opcEqual + opcJump + opcJumpIfFalse + opcIncrLocal` at 1M each. Ideal fused loop would be 3 opcodes/iter; actual is 8 opcodes/iter (~2.7x worse).

**Investigation needed:** Dump bench chunk (not just main chunk) to see exact bytecode sequence. Possibly compiler emits both paths OR `opcForLoopCond` doesn't fully fuse.

### 3. Superinstructions working
`opcAddLocalLocal` fires 1M = `s := s + i` fused correctly.
